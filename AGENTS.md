# CompliVibe Codex Instructions

Before doing any frontend UI, layout, dashboard, component, page, or styling work, read and follow `style.md`.

`style.md` is the CompliVibe frontend design constitution. It defines the visual system, layout rules, component rules, API state rules, loading/error/empty behavior, and QA checklist.

Do not create UI that violates `style.md`.

For every UI task:
1. Read `style.md`.
2. Inspect existing components.
3. Reuse shared components where possible.
4. Use real API data only.
5. Run build.
6. Open in browser.
7. Capture screenshot.
8. Report visual issues before moving to the next phase.
